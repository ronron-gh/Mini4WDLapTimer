# ミニ四駆ラップタイマー 要求仕様

本書は議論で決まった要求仕様を記録する。設定値のうち実測で決めるものと、実装時に選定する詳細は末尾に分けて記載する。

## 機器と設置

- M5StackとVL53L0X ToFセンサーを使用する。
- センサーはコースのスタート地点に、コース面に対して下向きに設置する。
- センサー下を通過する車体を距離の変化から検出する。
- 単一車体を対象とする。複数車体の識別・同時計測は行わない。

## センサーの起動と継続動作

- Pololu VL53L0Xライブラリを使用する。
- センサー初期化・測定時間設定・Continuousモードの開始は、起動処理を関数化して起動時に一度だけ実行する。
- Continuousモードは維持する。10周終了、Aボタン操作、計測の中止によって停止・再起動しない。
- この構成により再計測時の不正値が解消したことを実機で確認済み。
- 現設定は測定時間設定値20ms、I²Cクロック400kHz。実効取得周期が20ms未満であることを実機で確認済み。
- 計測時刻にはµs単位の起動後経過時間を使用する。カレンダーの実時刻は必要としない。

## 状態とAボタン

状態は「待機」「スタート待ち」「計測中」「完了」「エラー」とする。

| 状態 | 動作・表示 | Aボタン操作 |
| --- | --- | --- |
| 待機 | 起動直後の状態。1周目の測定値を0.00秒として表示する。車体通過では計測を開始しない。 | 基準距離を測定し、スタート待ちに移る。 |
| スタート待ち | 最初の車体通過を待つ。 | 現在の待機を中止し、基準距離を再測定してスタート待ちに戻る。 |
| 計測中 | ラップを記録し、スタートから現在までの経過時間を表示する。 | 計測を中止し、結果をクリアして基準距離を再測定し、スタート待ちに戻る。 |
| 完了 | 10周の結果と、10周終了時点の経過時間を保持・表示する。 | 結果をクリアして基準距離を再測定し、スタート待ちに戻る。 |
| エラー | センサー異常を表示し、計測を終了する。 | 基準距離を再測定し、スタート待ちに戻る。異常が続く場合は再びエラーにする。 |

- スタート待ちへの移行時は、前回のラップ記録・経過時間・通過判定状態をリセットする。
- 基準距離を測定するときは、センサー下に車体がいない状態を前提とする。
- 基準距離の取得中にセンサー異常が発生した場合もエラーにする。

## 通過判定

- Aボタン操作時に、車体がいないコースまでの距離を10サンプル測定し、その算術平均を基準距離とする。
- 基準距離より測定距離が一定量短くなった場合に車体を検出する。
- 検出に用いる距離差は、ソースコード上の固定定数として暫定20mmとする。基準距離から20mm以上短くなった場合に検出する。値は後で実測して調整する。
- 1回の車体通過につき1イベントだけ発行する。
- 通過を検出した時点から1秒間は、次の通過を検出しない。スタートとなる最初の通過にも適用する。
- 次の通過を受け付けるには、1秒経過に加えて車体の離脱を確認する。車体が下に留まっても、1秒後に同じ車体を再検出しない。
- 検出と復帰には異なる距離しきい値を使う（ヒステリシス）。復帰の距離差はソースコード上の固定定数として暫定10mmとし、基準距離からの短縮量が10mm以下になった場合に離脱と判定する。値は後で実測して調整する。
- 1秒の検出禁止中もセンサー取得は続ける。

## ラップ計測

- スタート待ち中の最初の車体通過をスタートとして、計測を開始する。この通過ではラップを記録しない。
- その後の通過を1周目、2周目、…として数え、10周までのラップタイムを記録する。
- 各周について、直前の通過からのラップタイムと、スタートからその周の通過までの累積経過時間を記録する。
- 1周目のラップタイムと累積経過時間は同じ値になる。
- 10周目の通過でラップ計測を終了し、結果を保持する。センサーの連続測定は維持する。
- 結果はRAMに保持し、永続保存は行わない。

## LCD表示とシリアル出力

- 時間の単位は秒とし、小数点以下2桁（100分の1秒）まで表示する。
- 1画面に10周分のラップタイムと各周の累積経過時間を表示する。ページ切り替えは使用しない。
- 起動直後は1周目のラップタイム・累積経過時間を0.00秒として表示する。
- 計測中はスタートから現在までの経過時間を継続して表示する。
- 完了時は10周終了時点の経過時間を保持する。
- センサー異常が発生した場合は、エラーを表示する。
- LCD左下のAボタンに対応する位置に、押したときの動作を表示する。待機状態では「スタート」、スタート待ち・計測中・完了・エラー状態では「リセット」とする。
- 通常のシリアル出力は、基準距離10サンプルの平均計測結果をmm単位で、基準距離確定後に各計測世代につき1回出力する。
- LCD相当のラップタイム・経過時間などのシリアル出力処理はデバッグ用に残し、通常は呼び出しをコメントアウトする。処理本体は削除しない。
- LCD描画とシリアル出力が測定処理を待たせたり、測定周期を低下させたりしない構成とする。

## センサー異常

- センサー異常・読み取りタイムアウトを検出した場合は、エラー状態に移り、ラップ計測を終了する。
- 異常な距離を通過イベントとして扱わない。
- Aボタンでスタート待ちへの復帰を試みる。センサーの停止・再初期化・再起動は行わない。
- ライブラリの高水準APIで検出できる取得エラーを扱う。距離品質判定や通信異常の検出範囲は、ライブラリの機能に制約される。

## 測定周期計測の開発用ビルド

- 既存の50回連続測定・CSV・集計を開発用ベンチマークとして保持する。
- 通常ラップタイマーとベンチマークはコンパイル時に選択する。実行時のCボタン長押しによる切り替えは廃止する。
- 通常用ビルドは従来どおり待機画面で起動し、Aボタンでスタート待ちへ移る。
- ベンチマーク用ビルドは起動後に自動で50回測定し、時刻・距離をRAMへ保存して終了後にCSVと集計を出す。
- 測定中はLCD描画とシリアル出力を停止する。測定と表示は別タスクとし、Continuousモードは起動時に一度だけ開始する。
- ベンチマーク用ビルドのAボタンは再度50回測定を行う。準備・測定・出力中は次の1回を予約し、連打は1回にまとめる。
- 終了画面左下は「A 再測定」を表示する。Cボタンは両ビルドで使用しない。
- 通常機能へ切り替えるには通常用ファームウェアを書き込む。ベンチマーク用ビルドを本体リセットすると、ベンチマークを自動で再実行する。
- センサー設定、50行CSV形式、読み捨て、NOT_RUN、集計方法は維持する。

## RTOSタスク構成

- 測定処理と表示処理を別のRTOSタスクに分ける。
- 測定タスクがセンサー取得・通過判定・計測状態・ラップ記録を管理する。
- 表示タスクがLCD表示とシリアル出力を行う。
- 測定タスクはLCDを操作せず、表示タスクへ状態とラップ記録のスナップショットを渡す。
- 表示更新用の通知は測定側をブロックしない方式とする。
- 未表示のラップも測定側の記録に保持し、通知の省略でラップ記録を失わない。
- ボタン入力は測定タスクへイベントとして渡す。

## 実測・実装時に決める詳細

- 設置距離と車体通過時の距離差の実測、および暫定しきい値（検出20mm・復帰10mm）の調整。
- LCDの具体的なレイアウト・文字サイズ・更新周期、シリアル出力の形式と頻度。
- タスクの優先度・実行コア・スタックサイズ、スナップショットとボタンイベントの受け渡し方法。
